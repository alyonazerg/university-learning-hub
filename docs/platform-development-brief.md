# Moon Campus: бриф для дальнейшей разработки

**Версия: 12 октября 2026.** Владелец продукта — преподаватель. Платформа обслуживает восемь учебных групп; основной контекст — грамматика первого курса и практика речи второго. Цель — вести занятия, задания и посещаемость, проводить revision tests, проверять работы и исследовать влияние предварительного чтения на использование изученной лексики и грамматики.

Этот документ фиксирует решения из рабочей переписки и реализацию в репозитории на указанную дату. Он не подтверждает, что последний коммит уже установлен на VPS. Статус производственного сервера необходимо проверять отдельно. Документация ранних этапов местами описывает scaffold и демоверсии: не принимать её за текущий статус подключённого кабинета.

## 1. Пользователи и реальные условия

Преподаватель работает с разных компьютеров, включая рабочий; записи и оценки должны жить на сервере. Студенты преимущественно проходят тесты с телефонов. Интернет слабый, иногда преподаватель раздаёт его через роутер с SIM-картой. Поэтому важнее надёжное сохранение, небольшой трафик и понятный экран, чем анимации и тяжёлые компоненты.

Публичные revision tests открываются без входа на платформу. Общая ссылка для всех: `https://mooncampus.ru/revision-test.html`. Студент выбирает группу и доступный тест. Поле имени имеет пример `Ivan Ivanov`; согласие на исследование выбирается явно. Для нового старта обязательны имя и выбор согласия. Списки студентов преподаватель вводит приватно сам; публичный экспорт ФИО не разрешён.

Сохранённая попытка сначала показывает свою принадлежность и кнопку продолжения. Новая попытка не должна возникать до заполнения обязательных полей. Потеря связи не должна стирать ответ или выдавать ложное сообщение об успешной серверной записи.

## 3. Учебная терминология и календарь

- Срез называется **Assessment Test**; тест перед срезом — **Midcheck**. Credit остаётся Credit; в конце учебного года предусмотрен Exam.
- Assessment Test длится 90 минут, дату задаёт преподаватель.
- IMT quiz presentations — обычное занятие, студенты представляют свои квизы.
- Для второго курса по практике речи два среза в семестре. Четыре revision tests: **RT1** после Unit 7, **RT2** после Unit 8 — первый срез, **RT3** после Unit 9, **Final RT** общий Units 7–9 — второй срез. Каждый даёт максимум 3 рейтинговых балла, всего 12.
- Первый срез примерно в середине семестра. Не фиксировать автоматически даты по прежнему ориентиру «середина октября» без проверки актуального расписания.
- Расписание должно охватывать все восемь групп, грамматику и практику речи. Время — Europe/Moscow. Особые совместные занятия нельзя дублировать как три одновременных события.
- Lesson topics: импорт CSV/XLS/XLSX с явным описанием колонок и примером. Mark as taught имеет заметный статус; массовая отметка присутствия должна реально сохраняться.

Часть этих пожеланий реализована в существующих модулях, но следующему разработчику нужно сверять каждый пункт по коду и данным, а не считать переписку доказательством завершения.

## 4. Материалы и группы RT1

| Группа | Учебник | Условие исследования |
|---|---|---|
| 213 | Evolve 6 | experimental |
| 214 | Evolve 6 | control |
| 215 | Evolve 5 | experimental |
| 216 | Evolve 5 | control |
| 217 | Evolve 5 | control |

Emergent vocabulary различается по группам: фильтровать задания, AI targets и аналитические метки по группе конкретной попытки. Грамматика Evolve 6: limiting/negative adverbial fronting и place/movement fronting. Evolve 5: infinitives/gerunds после разных частей речи, another/other и подобные формы, conditionals и if + will, articles. У 216 another/other не проходили: избегать такого акцента, текущий вариант компенсирует артиклями.

Вопросы должны проверять смысл, сочетаемость и использование. Нежелательны изолированные определения с требованием вспомнить одно слово без опоры, варианты с единственным знакомым словом, очевидные auxiliary gaps. Для strike a chord проверять значение и контекст, не предлог. В C1 онлайн-грамматике вводится целая конструкция или переписывается предложение; учитывать, где инверсия обязательна, а где обычный порядок грамматически допустим.

Ситуации для диалогов: общая Situation и различающиеся задачи Student A/B. Индивидуальные вопросы — развёрнутые, как в присланном экзаменационном образце. Для Units 7–9 подготовлены отдельные разрезные банки обоих учебников. RT1 использует Unit 7. Новые темы сверять с учебником и материалами преподавателя, не выдумывать названия юнитов.

## 5. Оценки: обязательный контракт

| Компонент | Максимум |
|---|---:|
| Vocabulary and collocations | 40 |
| Grammar | 25 |
| Group emergent vocabulary | 15 |
| Vocabulary and grammar вместе | 80 |
| Essay | 20 |
| Individual speaking | 20 |
| Dialogue | 20 |
| Speaking overall — среднее двух частей | 20 |
| Written result — 80-компонент + эссе | 100 |
| Рейтинг за весь RT | 3 |

Формула рейтинга: `(vocabulary_and_grammar + essay + speaking_overall) / 120 × 3`, округление до двух знаков. Это рассчитанный вклад, не автоматическое изменение внешнего университетского журнала. Неоценённое, неявка и незавершённая попытка — не ноль; финальный результат ждёт обеих частей Speaking и эссе.

Эссе: **Content, Organisation, Grammar, Vocabulary**, каждый 0–5. Индивидуальный ответ: **Vocabulary, Grammar, Coherence, Content**, каждый 0–5. Диалог: **Vocabulary, Grammar, Coherence, Communication strategies**, каждый 0–5. Критерии — только целые числа; нельзя менять оценку колесом мыши/спиннером. Speaking overall — среднее целых итогов, округление .5 вверх.

Исторические данные могут содержать прежние пять устных критериев, общий балл без разбивки или неполные новые поля. Сохранять их как есть; не выдумывать баллы критериев и не скрывать уже имеющийся диалог. Частичное сохранение одной части не стирает другую.

## 6. Устная часть: точная последовательность

1. После письменной сдачи преподаватель вызывает студента. Тот открывает индивидуальный вопрос при вызове и отвечает сразу 60–90 секунд, без подготовки.
2. Преподаватель сохраняет все четыре индивидуальных критерия. Повторяет для второго студента. Одновременное окончание письменной части не требуется.
3. В Results → Pair students выбирает группу и двух уже индивидуально оценённых студентов. Первый не доступен во втором списке. Для нечётного участника предусмотрен Teacher.
4. Назначение открывает Speaking с двумя диалоговыми блоками рядом на большом экране и вертикально на телефоне. У каждого свои критерии, feedback и отметки использования preview targets; одна кнопка сохраняет обе оценки атомарно.
5. Обеим сторонам выдаётся одна ситуация, но сервер передаёт каждому только его роль. Таймер общий: после открытия обеими сторонами 30 секунд чтения, затем 60 подготовки, затем 2–3 минуты диалога.
6. Статус после reload берётся с сервера. Оценённый индивидуальный ответ не раскрывается заново; общий балл Speaking означает завершение устной части. Завершённый диалог не предлагается повторно.

Ограничение «сначала индивидуальные оценки» применяется к новому назначению. У существующих пар диалоговые оценки должны оставаться видимыми даже при старом формате индивидуального итога. Удаление партнёра освобождает назначение, но не стирает чужие уже выставленные баллы.

## 7. Эссе и AI

Около 250 слов, ориентир 225–275. Четыре выбираемых темы на учебник; тема заметно выделена, счётчик слов обновляется при вводе, критерии доступны студенту. Тексты тем во всех бумажных версиях должны совпадать с сайтом.

AI подключается приватными переменными `REVISION_AI_API_KEY`, `REVISION_AI_MODEL`, `REVISION_AI_BASE_URL` на сервере. Провайдер OpenAI-compatible. Не отправлять ключ в клиент или переписку. AI получает учебный контекст и текст, без имени/списков студентов; использование внешнего провайдера требует корректной информации для пользователей.

AI возвращает предварительные критерии и feedback; только сохранение преподавателем делает оценку финальной. Проверять изученную лексику и грамматику данной группы, точные цитаты и качество употребления. Три разных естественно использованных единицы — сильное свидетельство для высокой Vocabulary; аналогично разнообразные корректные грамматические конструкции. Число единиц не заменяет рубрику. Бессмысленный ввод не должен получать высокий балл только за наличие текста. Короткие содержательные ответы нельзя механически обнулять по длине.

Вставка и перетаскивание в поле эссе блокируются с предупреждением о самостоятельном написании без ИИ. События потери фокуса/смены вкладки учитываются, но мобильные звонки, уведомления и системные действия могут давать те же события. Не назначать автоматические штрафы и не называть эту телеметрию доказательством использования ИИ.

## 8. Исследование и согласие

Выбор добровольный и не предвыбран. Отказ не влияет на оценку и не переводит студента в исследовательский контроль. Учебные данные и проверка сохраняются; исследовательская выгрузка включает только согласившихся. После выбора не повторять назойливую кнопку отказа внутри каждой задачи. Предусмотренный отдельный отзыв участия исключает из будущих исследовательских выгрузок; уже скачанные копии преподаватель должен обработать отдельно.

Experimental preview — естественный короткий связный текст, не механический набор целевых слов. Его показывают только соответствующим согласившимся участникам перед тестом, затем убирают. Состав snapshot и фактические условия не менять задним числом.

В эссе подсвечивается возможное употребление preview vocabulary/grammar; преподаватель подтверждает наблюдения. Для индивидуального ответа и диалога есть отдельные чек-листы. Пустой подтверждённый список означает «проверено, не обнаружено», отсутствие проверки — missing, не ноль. Автообнаружение и предложение AI не считать подтверждённой продукцией или причинным эффектом прайминга. Для контроля допустим сопоставимый список targets, но без ложной отметки exposure.

Метрики: начало/сдача, длительности теста/эссе/вопросов, первое взаимодействие, посещения вопроса, события ввода, связь/offline, возобновления, word count, языковые показатели, ответы, оценки, condition, версия/формат, preview exposure и наблюдения. Это клиентские измерения, не лабораторное время обработки; отсутствие старой метрики — missing. Бумажный и онлайн-формат, разные уровни, версии и объём выборки учитывать отдельно. Сравнение средних само по себе не доказывает эффективность вмешательства.

## 9. UX и результаты

Кабинет тестов: Tests / Results / Analytics / Settings. В Results один выбранный студент, внутри Essay / Speaking / Answers / Research. Разделять основные действия и редкие административные операции; не увеличивать количество кнопок и вложенных раскрывашек с каждым улучшением.

Answers — таблица с границами. Analytics — группы/все группы и один/все тесты, разделы и слабые задания с числом наблюдений. Цвета описательные: <50% красный, 50–74% янтарный, ≥75% зелёный, pending серый. Малую выборку явно обозначать. Не смешивать missing с неверными ответами.

Студенческий финальный экран компактный: submitted, рейтинг/pending, refresh и необходимое действие Speaking; подробности отдельно. После завершения — зелёный статус без пустых карточек и инструкций о будущей паре. Критерии эссе, индива и диалога отдельно в фиксированном порядке; на мобильном вертикально. Между subtotal, кнопкой приватной ссылки и ссылкой на кабинет есть отступы.

## 10. Сессии, возврат и удаление

Учительская сессия сохраняется при reload в sessionStorage на срок серверного токена — восемь часов. Ключ доступа туда не записывается. Logout/недействительный токен очищают запись; закрытие вкладки завершает её браузерное сохранение. С другого компьютера вход выполняется обычным способом, данные берутся с сервера.

Студент имеет секретный token отдельной попытки, локальный список My results и приватную ссылку с token во fragment. Это не сквозная синхронизация с аккаунтом; владелец полной ссылки имеет доступ. Потеря и браузерного хранения, и ссылки требует поддержки преподавателя.

Удаление попытки требует подтверждения и удаляет её ответы, оценки и исследовательские данные. Защищённые API должны отвергать старый token, клиент очищает соответствующие drafts/results. Видимая онлайн-страница проверяет статус каждые 30 секунд и при focus. Мгновенное обнаружение удаления offline невозможно; после связи удалённая работа не может сохраниться или сдаться.

## 11. Бумажный резерв

Текущий основной ZIP содержит **11 файлов**: пять DOCX групп, два A4 duplex PDF эссе (по учебнику), официальный 20-question ZipGrade PDF, DOCX-инструкцию и два зашифрованных файла преподавательских ключей. Пароль передаётся отдельно; не помещать его или открытые ключи в публичный репозиторий. Дубли question papers, отдельные preview, альтернативные A5 и банки speaking исключены из основного ZIP, доступны отдельными файлами.

Для 213 и 215 preview встроено после блока согласия; отказавшиеся пропускают. Отделить первую страницу и собрать после чтения до выдачи заданий. Контрольные 214/216/217 без preview. На листах заданий ответы не пишут: 1–20 отмечают A–E на официальном ZipGrade. 8 лексических/коллокационных, 8 грамматических, 4 emergent; считать разделы с весами 40/25/15, не использовать сырой /20 как рейтинг.

Эссе отдельное двустороннее A5: печатать A4 landscape, 100%, переворот по короткому краю, затем разрезать — два бланка на лист. Сначала пробная печать. Сохранить четыре актуальных темы сайта и поле выбора номера темы. При обновлении задания синхронно обновлять ключи и оба распространяемых ZIP; проверять сохранение шифрования ключей.

## 12. Надёжная разработка и доставка

- Изучить скилл, бриф и соответствующий код. Изолировать изменения, не коммитить временные файлы, virtualenv, node_modules и реальную учебную информацию.
- Новое содержание — для новых попыток. Начатые/сданные сохраняют snapshot. Миграции обновляют только нетронутые defaults и не начатые попытки, сохраняют ручные правки, проходят повторный запуск. Alembic revision не длиннее 32 символов.
- Для оценивания проверить partial/full, zero/pending, сохранность второй части, legacy marks, разные consent, связь пары и атомарное сохранение.
- Для клиента проверить 320/390 px и desktop, reload, сетевой сбой, отсутствие пустых блоков/overflow, серверный статус. Обновлять query-version JS/CSS в HTML.
- Не добавлять тесты ради зеркалирования реализации, но изменения жизненного цикла, доступа, оценивания и миграций требуют содержательной проверки.

Пример проверок для revision changes:

```bash
PYTHONPATH=backend .venv/bin/python -m pytest backend/tests/test_revisions.py backend/tests/test_revision_preview_migration.py -q
node --test tests/frontend/revision-test.test.cjs tests/frontend/revision-dashboard.test.cjs
```

Путь Python/Chromium зависит от окружения: подготовить зависимости по requirements и package.json, не предполагать наличие .venv. OCR assets собираются отдельным frontend build; не загружать OCR в публичный revision test без необходимости.

Команда пользователя на VPS:

```bash
cd /opt/moon-campus
git pull --ff-only origin sprint-2-registration
docker compose -f docker-compose.yml -f compose.beget.yml up -d --build
```

После реального деплоя проверить health, логи запуска миграций, вход, новый/сохранённый тест и результат. Push и успешные локальные тесты не доказывают успешный deploy. Не выполнять разрушительный reset данных для исправления интерфейса.

## 13. Приоритеты следующих итераций

1. Реальная проверка актуальной версии на VPS с согласившимися/отказавшимися, двумя телефонами, повторным входом и уже выставленными оценками. Проверить CORS и используемые HTTP-методы на производственном маршруте: конфигурации разных частей проекта могут отличаться.
2. Продолжать упрощение кабинета без потери оценок; поддержать старые данные и отдельные feedback каждой устной части. При загрузке по Attempt ID обеспечить загрузку партнёра без дубликатов.

### Обратная связь действий и диалог с преподавателем

В паре student–teacher кабинет показывает ситуацию и обе роли, преподавателю явно назначена B. Студент получает только A. Финальный экран благодарит за участие; written completion и полный completion не смешиваются. Общий action-feedback.js даёт реакцию save/refresh подключённого кабинета и revision test: pending, затем success/error, без ложного сохранения и повторной отправки. Полноценная очередь устной части остаётся будущей задачей.
