# Проверка Moon Campus — 12 октября 2026

Проверены исходники и локальные сценарии платформы, содержание текущих Unit 7 revision tests, бумажные варианты и доступные публичные страницы работающего сайта. Проверка производственной базы с учительским входом не выполнялась; новая попытка на работающем сервере не создавалась. Подключение платного AI и внешнего Grammar Lab не проверялось реальным запросом провайдеру.

## Подтверждено на работающем сайте

- revision-test.html, learning.html и API health отвечают HTTP 200.
- Открыты два RT1: Evolve 6 для 213/214 и Evolve 5 для 215/216/217.
- Общий вход выбирает группу и тест; имя показывает Ivan Ivanov; исследовательское согласие не предвыбрано.
- Публичный селектор не имеет горизонтальной прокрутки при 320, 390, 1280 px. Проверенные публичные страницы не вызвали ошибок JavaScript.
- Публичные HTML ссылаются на revision assets версии 20261012-04. Это проверка этих ресурсов, а не доказательство применения всех миграций или деплоя текущего коммита.
- Обнаружена реальная ошибка: DELETE preflight с Origin https://mooncampus.ru получает HTTP 400. Исправление CORS подготовлено в репозитории; на сервере заработает после обновления.

Для просмотра публичных страниц браузером в окружении проверки пришлось учитывать TLS-доверие локального сетевого посредника; это не установлено как дефект сертификата сайта. HTTP-проверка через доверенный клиент прошла.

## Исправления

1. В allow_methods API добавлен DELETE. Авторизация операции сохранена; неизвестный Origin остаётся запрещён. Проверка без авторизации получает 401.
2. Пересчёт использует новый ключ только при совпадении формулировки, вариантов и групп задания. Старую версию нельзя пересчитать по ключу совершенно нового задания с тем же ID.
3. В шести C1 inversion gaps теперь явно указан субъект I/WE/SHE/HE/YOU/THEY: студент не должен угадывать местоимение, которого нет в исходном предложении.
4. Одиннадцать оставшихся collocation questions заменены контекстными заданиями вместо механического выбора неправильного предлога/неестественной формы. Уже изменённый strike a chord сохранён. Resemble и raised the bar тоже проверяют смысл, а не единственный грамматически возможный вариант.
5. Миграция 018_material_audit обновляет только нетронутые definitions и не начатые попытки. Сданные/начатые snapshot и ручные правки сохраняются. Автоматического пересчёта старых результатов нет.
6. Соответствующие бумажные задания синхронизированы. Буквы ключей остались прежними; все 100 правильных ответов пяти групп сверены с приватным ключом.
7. Исправлены устаревшие сценарии тестирования: прежние названия полей/кнопок, старое автоматическое ожидание партнёра, отсутствие выбора темы эссе; тест XP не зависит от реального часа запуска. Проверка отступов ждёт завершения обновления кабинета, а не измеряет удалённый DOM.

## UX/UI: приоритет дальнейшей работы

Главный принцип: кабинет показывает следующую учебную задачу, а не набор технических операций. Сохранить лёгкий HTML/CSS/JS и устойчивость на мобильном интернете.

### Первая итерация: проведение занятия

- Список/очередь группы: письменная часть сдана → индивидуальный ответ → готов к паре → диалог → проверено. Увидеть имя, статус и необходимое действие без раскрытия каждой попытки.
- Не оценивать пропуск как ноль. Сортировка очереди по доступности с ручным изменением порядка; отсутствие одновременного окончания теста допустимо.
- Сохранить выбранную пару в постоянной панели с двумя критериями и одной общей кнопкой. Возможность вернуться к очереди без потери введённых черновиков.
- Индивидуальные критерии сохраняются отдельно; общий результат пары не заменяет индивидуальные оценки. Критическое подтверждение баллов остаётся явным.
- Использовать компактный список вместо нескольких похожих selectors. Технический Attempt ID оставить в деталях/поиске.

### Вторая итерация: понятный результат

- Рейтинг /3 и чёткий статус первым; затем три компонента, а не несколько конкурирующих итогов /80, /100, /20 без объяснения.
- Если результат pending, указать конкретную причину: эссе / individual / dialogue. После полного завершения убрать все инструкции к будущим этапам.
- Цвета с текстом и значком: фиолетовый действие, зелёный завершено, янтарный ожидание, красный ошибка. Не кодировать значимость только цветом.
- Общая система интервалов, типографики, высоты полей и состояния кнопок. Проверить contrast, keyboard focus, touch targets и screen-reader labels; не заявлять соответствие WCAG без измерений.
- На телефоне один основной шаг и кнопка, подробности доступны по запросу. Статус сохранения различает серверную запись и только локальный draft.

### Третья итерация: полезная аналитика и помощь

- От слабого задания переходить к ответам соответствующей группы; показывать, сколько студентов ошиблись и какое правило/значение требует повторения.
- Подсказки преподавателю: «эссе ожидают проверки», «два студента готовы к диалогу», «у группы повторяется ошибка». Не множить кнопки и уведомления.
- AI помогает собрать черновик feedback с цитатами и target evidence; преподаватель подтверждает. Прогресс не должен зависеть от доступности AI.
- Раздельные teaching/research views, сопоставимые версии/форматы и sample sizes. Не превращать описательные цифры в автоматический вывод об эффективности эксперимента.
