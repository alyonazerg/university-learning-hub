# Midcheck and the existing Grammar Lab

Midcheck plan cards expose Grammar Lab Topic 1 through a local, responsive diagnostic page. Source: https://github.com/alyonazerg/grammar (topic1/app.js, timing.js and index.html, retrieved 11 October 2026). The page uses the existing Supabase project's public publishable configuration and the existing get_active_assessment, get_assessment_timer, submit_grammar_attempt, get_attempt_review and save_attempt_question_times RPCs. No Supabase schema, permissions, service credentials or teacher credentials are changed.

GET /learning/midcheck/context requires a Moon Campus session. It derives students' registered pseudonym and group on the server, refuses other groups and only enables grammar groups 150/151/154. Teacher context selects a preview that sends no attempt. The identity context is passed in a URL fragment, not a query string, and the page has no-referrer policy. The legacy backend's p_full_name parameter receives the two-word learning alias; no identity-registry name is read. The public diagnostic RPC remains the existing Grammar Lab submission mechanism; this context endpoint does not replace its authorization model.

Questions, scoring, reviews and timing remain in Grammar Lab. Results are not automatically copied into Moon Campus coursework grades, and completing the diagnostic does not mark the class taught. Teacher preview reads active questions and timer settings but does not submit attempts or timing. Automated browser tests mock Supabase writes; verification against the live project reads the active question set only.

Mark everyone present now commits all active learners' present marks in one existing attendance PUT, then refreshes the cabinet. With no learners, the button is disabled. Manual individual changes still use Save attendance. Completed lesson cards receive a visible checkmark and green treatment in both Plan and Schedule; toggling completion keeps using the existing durable plan API.
