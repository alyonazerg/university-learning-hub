# Moon Campus — рабочая память

Обновлено 12 октября 2026. Основной бриф: `docs/platform-development-brief.md`; подробности тестов: `docs/revision-tests.md`. Относительные пути в этом скилле относятся к корню репозитория. При противоречии пользовательских указаний и этой памяти следовать пользователю; код и текущие проверки определяют фактическую реализацию.

## Начало работы

Прочитать бриф, нужные исходники и ближайшие AGENTS.md. Не считать исторические описания scaffold/React planned/неразвёрнутый API актуальным статусом. Пользователь общается по-русски; интерфейс теста по-английски. Обращаться к задаче как к поручению: доводить разрешённую работу до результата, не предлагать выполнить её позже. Не требовать повторных подтверждений для уже разрешённых правок. Не выдумывать выполненный деплой, доступ к серверу или проверку производственной БД.

Учитель: `frontend/learning.html`, тест: `frontend/revision-test.html`. `revision-session.js` — кабинет тестов; `revision-test.js` — студент; `revision-tests.css` — стили; `backend/app/revisions.py` — API. Материалы `backend/revision_materials/`, печатные файлы `frontend/templates/`.

Репозиторий alyonazerg/university-learning-hub. В этой сессии разрешена отправка в `sprint-2-registration`. Локальная рабочая ветка может называться иначе: проверять git status, не коммитить чужие изменения и временные симлинки .venv/node_modules. PUSH НЕ РАВЕН DEPLOY. Если нет действующего доступа, дать пользователю команды, не утверждать обновление сайта.

## UX: обязательные решения

Приоритет — телефон и слабый мобильный интернет: малый вес, отсутствие ненужных зависимостей, сохранение ввода при сетевых сбоях. Не увеличивать количество основных кнопок и раскрывашек. Кабинет тестов: Tests / Results / Analytics / Settings; один выбранный студент, вкладки Essay / Speaking / Answers / Research. Понятно разделять инструкцию и текст вопроса, показывать варианты непосредственно на странице.

Оценки критериев — целые 0–5, не изменяются колесом мыши и спиннерами. Сначала сохранить четыре индивидуальных критерия каждому, затем выбрать пару в Pair students. Только оценённые студенты доступны для нового назначения; второй выбор исключает первого, нечётному — Teacher. Затем рядом две независимые формы диалога, одна кнопка Save both dialogue grades. На телефоне формы вертикальные. Сохранение пары атомарное, каждый получает собственные баллы. Существующие диалоговые оценки НЕЛЬЗЯ скрывать из-за отсутствующего старого индивидуального итога или освобождённой пары. Сохранённая индивидуальная оценка доступна для редактирования.

Студент получает общую ситуацию и ТОЛЬКО свою роль A/B: фильтрация на сервере, не CSS. Индивидуальный ответ 60–90 секунд без подготовки; диалог 30 секунд чтение + 60 подготовка + 2–3 минуты ответ. Общее чтение начинает таймер после открытия обеими сторонами. После обновления статус берётся с сервера; выставленная общая Speaking означает завершение устной части, индивидуальный вопрос и диалог не предлагаются снова. На завершённом экране нет пустых карточек и инструкций о будущей паре. Компактный зелёный статус; подробности результата отдельно. Критерии разделены по частям и идут в фиксированном порядке; ссылки и кнопки имеют отступы.

## Оценивание и исследование

Лексика/коллокации 40 + грамматика 25 + emergent vocabulary группы 15 = 80; эссе 20; индивидуальный ответ 20 и диалог 20, Speaking — среднее, .5 вверх. Рейтинг `(80-компонент + эссе + Speaking)/120*3`, два знака; неоценённое — pending, не ноль. Эссе Content/Organisation/Grammar/Vocabulary по 5. Индив Vocabulary/Grammar/Coherence/Content; диалог Vocabulary/Grammar/Coherence/Communication strategies по 5. Не перезаписывать исторические критерии выдуманным распределением.

213/214 Evolve 6; 215/216/217 Evolve 5. Эксперимент 213/215; контроль 214/216/217. Исследовательское согласие отдельное, без предвыбора, до создания новой попытки и preview. Отказ не переводит в контроль: учебные результаты остаются, исследовательские выгрузки исключают. Не повторять кнопку отказа после выбора; сохранять предусмотренную отдельную процедуру отзыва. Никаких ФИО, ключей API, токенов, ответов и выгрузок реальных студентов в git или публичные материалы. Списки пользователь вводит сам.

AI даёт предложение, учитель подтверждает. Проверять реально пройденную лексику конкретной группы и грамматику; три корректных разных единицы — сильное свидетельство, не автоматический максимум. Требовать цитаты, не оценивать бессмыслицу как нормальную работу. Preview usage отдельно для эссе, индивидуального ответа и диалога; галочки учителя — подтверждённое наблюдение, автоподсветка — лишь подсказка. Телеметрия клиентская, не доказательство причинного эффекта или списывания. Антивставка и события смены вкладки не доказывают использование ИИ, не дают автоматический штраф.

## Материалы, сохранность, проверки

Не делать задания на угадывание единственного знакомого слова или предлога strike a chord; проверять смысл/употребление с правдоподобными изученными альтернативами. C1 grammar — целая конструкция/перефразирование, не один auxiliary. Изменения тестов влияют на новые/не начатые попытки; начатые имеют неизменяемый snapshot. Миграции сохраняют учительские правки, идемпотентны, revision <=32 символов.

Бумажный архив — 11 файлов, не возвращать дубли: 5 DOCX групп, 2 PDF эссе A4 duplex, официальный ZipGrade 20 PDF, инструкция, 2 защищённых файла ключей. Preview внутри 213/215 после согласия; отказавшиеся пропускают. MCQ ответы только на ZipGrade; 20 вопросов A–E, 8/8/4, веса 40/25/15; эссе около 250 слов, выбор четырёх тем сайта. Duplex A4 landscape 100%, короткий край, разрезать на 2 A5. Не публиковать незашифрованные ключи, пароль хранить отдельно.

Проверять соответствующие backend pytest и Playwright Node tests; мобильную ширину 320/390 и desktop, перезагрузку, pending/0/исторические оценки, каждый вариант пары. После изменений JS/CSS обновлять версии ресурсов в HTML. Проверять zip состав, согласие/preview/темы эссе/ключи, не выдавать старый архив. Обновлять бриф/этот скилл при новых решениях, сообщать пользователю что изменилось, что проверено, что требует деплоя.

Печать: компактные основные задания — 3 страницы у 214/216/217 и 4 у 213/215 (с отдельным preview), A4, Arial 11 pt, поля 11.5/12.5 мм. Не разрывать вопрос и A–E, не уменьшать официальный ZipGrade. `scripts/compact_revision_papers.py` применяет форматирование без изменения текста. DOCX-комплекты по 11 файлов сохраняются; отдельный `Revision-Unit-7-Compact-PDF-Pack.zip` содержит 11 файлов с PDF заданий вместо DOCX, готов для печати. Не добавлять оба формата в один архив. При обновлении синхронизировать DOCX, PDF и все три ZIP, проверить число страниц и шифрование ключей.
